## Why

David, 08/09: the interface must show which features need extra configuration, a checklist of what is not configured yet and, for the administrator, how to configure it — and users must never meet a 4xx/5xx for a feature that is simply not set up. The Hostman logs of the same day showed the opposite: a 500 on Outlook (`MICROSOFT_INTEGRATION_CLIENT_ID` missing), a 503 with a prose message on pipelines, a 400 on webhooks that only made sense to someone who knows the code.

## What

- `apowerb/core/setup_status.py` — the checklist, computed from the **same predicates the features already use** (`default_llm_available`, `is_s3_artifact_storage_configured`, `orchestrator_is_configured`, `_smtp_configured`), so it cannot drift from behaviour: `default_llm`, `object_storage` (mode `local` | `s3`, informative, never blocking), `microsoft_integration`, `google_integration`, `orchestration`, `observability`, `system_mail`. Each line carries the feature keys it blocks and the **names** of the variables still unset. Values are never read into the response; a test asserts it with distinctive fake values.
- `GET /api/config/setup` (authenticated): everyone gets the flags — that is what lets a screen say « not configured yet, contact your administrator »; only an administrator (`is_admin`) gets the variable names. Closed schemas (`extra="forbid"`).
- `not_configured(key)` / `require_configured(key)`: a **503 carrying `{"code": "NOT_CONFIGURED", "capability": key}`** the front can recognise. Wired where an OAuth dance would otherwise start into a wall: `/microsoft/{service}/connect`, `/google/connect`, and `/emailing/microsoft/auth-url` (which answered 500). The orchestrator's own outage contract is left as is.

## Tests

`tests/test_setup_status.py` (10): every capability listed once; flags follow the predicates; local storage is the default and names what S3 would need; no value leaks even to an administrator; users get flags but no names; closed schemas; the 503 contract; the route refuses anonymous callers and distinguishes admin from user. `test_oauth_state_validation` stubs the guard in its fixture (those tests prove state persistence, not configuration). CI-equivalent suite: same reds as `origin/main`.
